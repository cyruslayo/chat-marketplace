# Use Weaver as the web A2UI runtime

Weaver replaces CopilotKit as the target web A2UI runtime. CopilotKit is removed from the target architecture, and AG-UI is no longer a mandatory client-to-agent protocol. A2UI v0.9.1 remains the declarative rich-interface protocol. Weaver remains behind platform-owned application boundaries; Weaver types and APIs must not enter authoritative domain models, application services, state machines, policies, payments, ledgers, or framework-neutral platform ports. Weaver is an interface runtime and transport integration, not a system of record.

Shortlet Booking domain services remain authoritative. `InteractionArtifact` remains the canonical application presentation input, and A2UI output is derived from authoritative application projections rather than becoming authoritative state. Consequential A2UI actions continue to resolve to `PlatformCommandEnvelope` commands. Authentication, authorization, schema and current-state validation, business policy, idempotency, concurrency, and audit remain backend responsibilities. Weaver must not calculate or alter Shortlet Booking eligibility, price, availability, deadlines, consent, rights, obligations, or any other business rule.

The Weaver Basic Catalog is approved for the first discovery migration. Custom shortlet catalogues are deferred until evidence shows that the Basic Catalog is insufficient. This deferral does not permit dynamic schemas, arbitrary executable UI, unsafe destinations, hidden controls, or automatic contractual or financial submission. Catalogue and semantic validation, safe fallback, and fail-closed action authority remain platform obligations.

Conventional deterministic web routes remain required fallbacks and must retain semantic command parity for every material and recovery-critical workflow. Rich-UI failure must not remove or corrupt authoritative workflow state. Unsupported, stale, superseded, or expired material actions continue to fail closed and require a fresh authoritative projection. The migration must preserve deterministic conventional-route parity and must not change Shortlet Booking business rules.

WCAG 2.2 AA, keyboard and assistive-technology support, reduced-motion and constrained-network behavior, English (Nigeria), `en-NG`, NGN in kobo, and `Africa/Lagos`/WAT requirements remain unchanged. Security, data minimization, human handoff, and backend observability requirements also remain unchanged.

Weaver transport facilities may support client reconnect behavior. Durable ordered replay, staging, compaction, deduplication, correlation, audit evidence, and recovery across server restarts remain host-owned platform responsibilities. Weaver integration must be proven independently replaceable: recorded A2UI interactions must produce equivalent platform commands and domain results through Weaver and a framework-independent harness, with no Weaver types in authoritative packages and with verified rollback.

This ADR supersedes ADR-0068 where it mandates AG-UI and selects CopilotKit as the launch web implementation. It preserves ADR-0068's platform-owned boundaries, A2UI representation, non-authoritative interaction state, backend command controls, safe fallback, and framework-removability constraints. It supersedes ADR-0069's mandatory `com.chat-marketplace.interaction/agui-v1` client-to-agent profile, AG-UI SDK requirement, and required HTTPS POST/SSE transport for the web runtime. It preserves ADR-0069's A2UI v0.9.1 decision and its versioning, validation, safe-rejection, security-review, canary, rollback, and retirement principles for supported interaction contracts.

This ADR modifies ADR-0071 and ADR-0072 only where they name AG-UI as the carrier or tool-call source; their projection, command, identity, and fail-closed constraints remain in force. It modifies ADR-0073 by approving Weaver Basic Catalog for the first discovery migration and deferring the five custom launch catalogues until insufficiency is demonstrated; all catalogue governance constraints remain in force. It modifies ADR-0079 and ADR-0080 only by replacing CopilotKit-specific validation and outage assumptions with Weaver-specific integration and framework-independent validation. ADR-0070, ADR-0074 through ADR-0078, and all Shortlet Booking business ADRs remain in force. Historical ADR text is not rewritten; this ADR records the changed target architecture.
