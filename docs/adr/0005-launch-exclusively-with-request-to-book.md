# Launch exclusively with Request to Book

All shortlet units use Request to Book at launch, enforced by platform policy rather than operator preference. A unit's calendar exposes only open dates; an operator must confirm a single exclusive request before the guest is invited to pay, and verified payment is required before a reservation exists. This favors protection from stale informal calendars and double bookings over maximum conversion, while response, reminder, and payment deadlines remain configurable around operator active hours.

Instant Book remains represented in the domain but is disabled platform-wide. It may later be granted and revoked per unit—not per operator—using observed calendar accuracy, response time, pricing consistency, cancellations, double bookings, inventory synchronization, and trust-and-safety history.
