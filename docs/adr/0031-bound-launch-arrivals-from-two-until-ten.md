# Bound launch arrivals from 2:00 PM until 10:00 PM WAT

The platform supports contractual first arrival only between 2:00 PM and 10:00 PM West Africa Time. Each unit publishes a Contractual Check-In Window within that boundary and may narrow but never extend it. Search accounts for expected arrival and handover method, and rejects known unsupported first-access requirements before identity verification or payment. The boundary is an operational launch constraint, not a general hospitality rule.

Early check-in means arrival before the unit's normal start but never before 2:00 PM. It requires operator confirmation, verified support coverage, a revised quote when priced, explicit guest acceptance, and a contract update. Scheduled first access after 10:00 PM is unsupported. Unexpectedly delayed guests use an exception workflow only when valid access was already provided or support coordinates an alternative; the product and agent never promise anytime arrival.

Bookings capture both earliest access and latest permitted arrival with the Africa/Lagos timezone. Operators maintain primary and backup contacts, access method, disclosed arrival ID checks, and delayed-guest procedures for the complete window. Human coverage includes configurable preparation and incident-resolution buffers and continues beyond its scheduled end while an active arrival incident remains unresolved.
