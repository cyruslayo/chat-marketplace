# Establish Pilot Operator Authentication and Session Authority

For the first-party 50–100 apartment pilot, Operator representatives are provisioned manually by an operational command and receive a cryptographically random, one-time access token out of band. The token is valid for 30 minutes, is bound to one human actor and tenant, is stored only as a secure hash, and is consumed atomically at `POST /operator/login`. Tokens are never placed in URLs or delivered by email, SMS, or another provider.

Successful login creates an opaque server-issued Operator session. Only the session-secret hash is durable; the binding records session, actor, tenant, creation, absolute expiry (12 hours), and optional revocation. The dedicated HttpOnly, SameSite=Lax cookie carries no actor, tenant, Operator, or permission claims. Sessions do not slide, and logout revokes the server binding before clearing the cookie. Restart preserves valid and revoked state. All tabs using the cookie resolve the same server-owned principal; revocation applies to every tab.

The session establishes only human actor and tenant identity. Every protected action resolves its target Operator from authoritative application data and independently evaluates the current ADR-0082 representative grant, requested scope, tenant, concurrency, and policy. Grant revocation therefore denies future actions without requiring session deletion. Missing, expired, consumed, revoked, or malformed credentials fail closed. Audit and telemetry record only safe identifiers and reason codes, never raw tokens, session secrets, or cookie values. The pilot mechanism is a replaceable authentication boundary; a future provider may replace token issuance and session establishment without changing ADR-0082 semantics.
