# Build agent modes on Baseline, enhance for Chromium

The late-2026 web platform can deliver every part of the agent-modes feature with standard HTML, CSS and a small vanilla client, but only if the design treats three primitives as Chromium-or-newer enhancements rather than foundations: `moveBefore()` (no Safari), scroll-snap events and scroll-state queries (Chromium only), and element-scoped view transitions (Chromium 147+ only). Everything the core needs is Baseline: attribute-scoped tokens with relative colour and `contrast-color()`, same-document view transitions, the Navigation API, `scrollend`, invoker commands opening a `<dialog>`, and native radio groups. Against the current design (`.scratch/agent-modes/architecture-analysis.md`), the research confirms the server-owned `ModePresentation` manifest, the `data-mode` token blocks, the inline-SVG Agent Mark and the guest-text-only lane boundary. It argues for five changes: open the bottom sheet as a modal `<dialog>` and drop its `history.pushState` entry; keep visited lanes as live hidden subtrees instead of detached DOM; store lane timelines and model history as one row per event instead of `timeline_json`/`history_json` blobs; cap the Mark's `thinking` loop at five seconds regardless of turn length; and present modes as one assistant with domain capabilities rather than separately named personas, since OpenAI and Google are retiring exactly that pattern this quarter. The audience sharpens every choice: Chrome holds about 64% of Nigerian mobile page views, Opera about 20% and Safari about 13% ([StatCounter](https://gs.statcounter.com/browser-market-share/mobile/nigeria)), so Chromium-only polish reaches most guests, iOS sets the fallback floor, and Opera Mini's server-rendered mode makes the no-JS path a real client, not a courtesy.

## Safari, not Android, sets the floor for three primitives

The Nigerian audience is unusually Chromium-heavy. StatCounter's July 2026 mobile figures give **Chrome 64.23%, Opera 19.87% and Safari 12.77%**, with Samsung Internet, UC and Firefox at about 1% or less each ([StatCounter](https://gs.statcounter.com/browser-market-share/mobile/nigeria)), and most Opera traffic is on recent Chromium-based 99.x versions ([StatCounter versions](https://gs.statcounter.com/browser-version-market-share/mobile/nigeria)). StatCounter measures page views on sites carrying its tracker, and no source split Opera Mini from Opera for Android, so the share of guests running Opera Mini's server-rendered mode, which executes almost no client JS, is unknown. Devices are cheap: four in five smartphones sold in Africa in 2025 cost under $200 ([TechCabal](https://techcabal.com/2026/02/25/in-2025-four-in-five-smartphones-sold-in-africa-cost-under-200/)), and current affordable Nigerian 4G models ship with 2–3 GB of RAM, some on Android Go ([Nairametrics](https://nairametrics.com/2025/11/01/top-10-most-affordable-4g-smartphones-in-nigeria-as-of-october-2025/)). The median mobile download is about **44 Mbps** ([BusinessDay](https://businessday.ng/technology/article/nigeria-slips-to-85th-in-global-internet-speed-rankings-as-peers-pull-ahead/)), but data is expensive after the January 2025 tariff rise, which lifted the average 1 GB price about 65% to roughly ₦475 ([The Condia](https://thecondia.com/mtn-nigeria-data-price-hike-2025/)). Bandwidth is not the constraint; bytes, CPU and RAM are.

That profile turns support tables into product decisions. The table below lists the primitives the feature touches, in order of how safely the core can depend on them.

Second, the JS budget should sit far below Alex Russell's global P75 ceiling of roughly 300–350 KiB gzipped ([Infrequently Noted](https://infrequently.org/2022/12/); [2024 summary](https://conffab.com/elsewhere/the-performance-inequality-gap-2024-infrequently-noted/)), because the chat shell is one of several things a guest's phone is doing on a paid data bundle.

## The manifest and token design holds; personas should become capabilities

The `ModePresentation` manifest is the right shape for the platform. Microsoft's published agent guidance says an agent's entry point needs "a clear name, description, and conversation starter prompts", that the small agent tag in the composer is "a key trust signal", and that "the UI always shows which agent is active" ([Microsoft Learn](https://learn.microsoft.com/en-us/agents/design-guidelines/agent-entry-points)). The manifest already carries label, tagline, empty-state starters and composer copy from one copy source, renders server-side into both the chat shell and the no-JS `/conversation` page, and sets `data-mode` on `<html>` in the first byte so the page never flashes the wrong mode. Keep it closed, static and colour-free, as ADRs 0073 and 0077 require.

The research supports the design's colour plan with one refinement. Plain attribute selectors (`:root[data-mode="stays"]`) have the widest support and do the whole job; container style queries only became Baseline in May 2026 and add nothing a `data-mode` hook cannot already do ([web.dev](https://web.dev/blog/web-platform-05-2026)). Relative colour syntax (`oklch(from var(--mode-accent) …)`) can derive `--mode-accent-subtle` and `--mode-tint` from one accent ([MDN](https://developer.mozilla.org/docs/Web/CSS/CSS_colors/Relative_colors)), and `contrast-color()` can produce `--mode-on-accent` behind `@supports`, but it returns only black or white aimed at WCAG AA ([web.dev](https://web.dev/blog/web-platform-04-2026)). Because iOS below 18 lacks relative colour and the design must also satisfy the regex-based foundation tests, the safest course is to precompute every `--mode-*` value as static declarations in the three existing places (light, forced dark, system dark) and treat the derived forms as an authoring aid, not runtime dependencies. The design's planned contrast test then runs against fixed values. Flip the accent by changing one attribute; do not transition many custom properties, which is costly on low-end CPUs.

`theme-color` deserves a downgrade. caniuse now marks iOS Safari 26.0 through 27.2 as **not supported**, after support in 15–18.7, and sources disagree on whether Safari 26 honours it for installed web apps ([caniuse](https://caniuse.com/meta-theme-color); [MDN BCD PR](https://gh.r-mj.com/mdn/browser-compat-data/pull/28503)). Updating it on a mode switch costs nothing on Chrome Android, but the design should treat it as decoration and let the app-bar background carry the tint on iOS, which now samples page colours.

The weightiest finding concerns the `persona` field. The two biggest named-persona containers are being retired this quarter: custom GPTs stop running on **11 December 2026** and migrate to plugin "skills", without carrying their previous conversations ([OpenAI Help](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq); [Virtualization Review](https://virtualizationreview.com/articles/2026/09/28/openai-to-retire-custom-gpts-replace-them-with-plugins.aspx)), and Gemini Gems "will be removed on personal Google Accounts starting in November 2026" and "transition to skills" ([Google Gemini Help](https://support.google.com/gemini/answer/15146780?hl=en)). The industry is converging on one assistant with domain capabilities. The steelman for per-mode identity is real: Microsoft 365 Copilot keeps agent names and icons because they tell the user who is acting ([Microsoft Learn](https://learn.microsoft.com/en-us/agents/design-guidelines/agent-entry-points)), and persona research warns that a persona without matching domain competence fails ([arXiv 2407.11977](https://arxiv.org/html/2407.11977)). The synthesis is to keep a distinct **mode identity** (mark silhouette, accent, label, starters, scope) because stays, restaurants and events are genuinely different workflows, while dropping **character personas**. In practice that means the manifest's `persona.name` reads as "Concierge · Stays" rather than a separately named agent, and the neutral platform preamble the design already proposes becomes the single voice. This also keeps prompt caching per pack, as the design intends.

## The Agent Mark should be inline SVG that stops moving within five seconds

The research validates the design's rejection of animation runtimes. Rive's smallest web runtime is **222 KB brotli** and its full canvas build 567 KB ([Rive docs](https://rive.app/docs/runtimes/runtime-sizes.md)); dotlottie-web adds about 33 KB of JS plus a WASM engine that LottieFiles describes variously as roughly 150 KB and roughly 500 KB compressed ([LottieFiles](https://docs.lottiefiles.com/en/runtimes/distributions/js/v0.x/core-concepts.md); [lottiefiles.com](https://lottiefiles.com/dotlottie)). All performance claims for these runtimes are vendor-authored. Both draw into a canvas that rasterises every frame and needs JS calls to retheme, whereas an inline SVG of a few KB inherits `currentColor` and `--mode-*` tokens for free. Chromium has hardware-accelerated SVG animation of `transform`, `opacity` and `filter` since version 89 ([Chrome for Developers](https://developer.chrome.com/blog/hardware-accelerated-animations?hl=en)), so loops on those properties stay on the compositor. `@property`-registered custom properties (Baseline July 2024) can animate a hue or conic-gradient angle, but those repaint each frame, so keep them to the small mark and pause them when idle ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/registered-custom-properties)). Use CSS keyframes keyed on `data-agent-state` for steady loops and the Web Animations API for state changes, because `getAnimations()` and `animation.finished` let a vanilla client cancel a `thinking` loop the moment `responding` arrives.

One rule in the current design needs tightening. WCAG 2.2.2 requires a pause, stop or hide mechanism for moving content that starts automatically, lasts more than **five seconds** and sits beside other content ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)). The design argues that `thinking` "lasts only as long as a request, which is bounded by the turn budget", but a model turn over a congested Nigerian cell routinely outlasts five seconds, and the transcript and composer remain usable alongside it, so the loading-screen exception does not apply. The fix is cheap: let `thinking` animate for at most five seconds, then settle into a static "thinking" pose while the existing `#working-status` text keeps the accessible signal. The rest of the state table aligns with the sources: pulses at or below 1 Hz to stay well clear of the three-flashes rule, a static glyph for every state under reduced motion, a still, non-AI badge for human takeover, and all loops paused on `visibilitychange`. Handle reduced motion explicitly for view transitions too; sources conflict on whether browsers adapt them automatically, and Nuxt and Shopify both skip `startViewTransition` under `prefers-reduced-motion: reduce` ([Shopify](https://shopify.dev/docs/storefronts/themes/best-practices/performance/cancel-view-transitions-on-interaction)).

For the switch morph itself, the design's `document.startViewTransition({ update, types: ["mode-switch"] })` with a callback fallback is correct for the base layer. On Chromium 147+, which covers most of the audience, prefer `shellEl.startViewTransition(...)`: element-scoped transitions pause only their subtree and can run concurrently, whereas a document transition makes the whole page non-interactive until it finishes ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using_element-scoped)). Calling it unguarded throws elsewhere, so feature-detect. Keep named elements to a handful (mark, app bar, composer, workspace); a community report saw frame drops near 20 named pairs on low-end phones, though that is anecdotal ([pravinkumar.co](https://www.pravinkumar.co/blog/view-transitions-api-webflow-spa-navigation-tutorial-2026-fa861)). Never run the Mark's state loop inside a view transition.

### The strip is a radio group; the sheet is a dialog without a history entry

The design's choice of native radios for the hero strip is the strongest-supported decision in the brief. APG gives radio groups arrow-key roving with selection following focus, and warns against automatic tab activation whenever switching has latency ([APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/); [APG Radio](https://w3.org/WAI/ARIA/apg/patterns/radio/examples/radio)). Sara Soueidan's audit found that CSS carousel markers are always exposed as tabs in a single-select tablist that usually controls nothing, and concluded that "semantics should be defined in HTML" ([Sara Soueidan](https://sarasoueidan.com/blog/css-carousels-accessibility)), so `::scroll-marker` should stay out of the switcher. The one technical update to the design concerns the swipe fallback: the design pairs Chromium's `scrollsnapchange` with an `IntersectionObserver` fallback, but `scrollend` now ships in every engine, Safari since 26.2 ([InfoQ](https://www.infoq.com/news/2026/04/safari-scrollend-support)), so commit on `scrollend` by computing the centred radio and use `scrollsnapchanging` only for the live highlight. Add `overscroll-behavior-x: contain` and inline padding so swipes start away from system edge gestures; the Android edge-back gesture cannot be blocked by a page ([Chrome for Developers](https://developer.chrome.com/blog/overscroll-behavior)). Haptics stay a feature-detected Android tick, since WebKit has not implemented vibration and Firefox removed it in 129 ([W3C](https://w3c.github.io/vibration/reports/implementation.html)).

The bottom sheet is where the research most directly contradicts the design. The design reuses an existing pattern, `history.pushState({shortletSheet: true})`, so that Back closes the sheet. Since Chrome 120, the Android back gesture is a **close request** that closes an open modal `<dialog>` through CloseWatcher, and Firefox has added the same behaviour ([Chrome 120](https://developer.chrome.com/blog/new-in-chrome-120); [Mozilla bug 1966073](https://bugzilla.mozilla.org/show_bug.cgi?id=1966073)). Adding a history entry on top risks double handling, and CloseWatcher's anti-back-trapping rules can skip `cancel` or close several watchers at once when there was no user activation in between ([blink-dev](https://groups.google.com/a/chromium.org/g/blink-dev/c/jM5au7yYzHM)). The recommended build is a `<dialog>` styled as a sheet, opened by `<button commandfor="agents" command="show-modal">`, with `closedby="any"` for light dismiss where supported and a click-outside handler for Safari, a visible Close button so drag-to-dismiss is never required (WCAG 2.5.7), and a plain link to a server-rendered picker page as the no-JS and Opera Mini path. On iOS, where there is no back button, the Close button and backdrop carry dismissal.

## Automatic switching earns trust only when it is visible and reversible

The best evidence on tiers comes from failures. GPT-5's real-time router in August 2025 turned a launch into "a product and trust crisis" because users could not see or control which model answered ([Fortune](https://www.fortune.com/2025/08/12/openai-gpt-5-model-router-backlash-ai-future)); within about a week OpenAI added Auto, Fast and Thinking pickers as a manual override ([iPhone in Canada](https://www.iphoneincanada.ca/2025/08/13/openai-gpt-5-new-auto-fast-thinking-modes/)). The September 2025 safety router repeated the pattern: routing ran per message and ChatGPT would say which model was active only "when asked" ([Simon Willison](https://simonwillison.net/2025/Sep/28/nick-turley/)), and subscribers accused OpenAI of "secretly switching" models ([TechRadar](https://www.techradar.com/ai-platforms-assistants/chatgpt/openai-responds-to-furious-chatgpt-subscribers-who-accuse-it-of-secretly-switching-to-inferior-models)). Microsoft's counter-pattern is a persistent agent tag plus a system **control message** whenever an agent joins or stops responding ([Microsoft Learn](https://learn.microsoft.com/en-us/agents/design-guidelines/agent-entry-points)).

The design's tiers already encode the lesson: tier A and B switches carry `modeChange`, morph the Mark, leave a divider row ("Now with the Events concierge") and offer an undo chip; tier C suggests and waits. The research adds three requirements. Switches should happen at topic boundaries and then stick, never flip per message, which the design's "at most one automatic switch per turn" and "no automatic switch back after a manual choice" rules approximate; LangChain's handoff pattern likewise keeps the active agent across turns so repeat requests skip re-routing ([LangChain](https://docs.langchain.com/oss/python/langchain/multi-agent)). The divider must be persistent state in the lane, not a transient toast, since "ask and it will tell you" disclosure failed. And the tier boundaries need data, not intuition.

That last point is the largest uncertainty in the feature. **No framework or paper found publishes routing thresholds, hysteresis settings or an auto/undo/suggest tier scheme**; the design is ahead of published guidance. Practitioner work does supply a method. LLM stated confidence is often poorly calibrated, but routing needs *selective* quality, meaning confidence ranks right answers above wrong ones, which can hold even when calibration is poor ([tianpan.co](https://tianpan.co/blog/2026-05-04-llm-classifier-production-beyond-accuracy)). Abstain thresholds should differ by class and be chosen from risk-coverage curves ([tianpan.co](https://tianpan.co/blog/2026-04-27-calibrated-abstention-i-dont-know)), and conformal methods give finite-sample guarantees from small calibration sets ([arXiv 2405.01563](https://arxiv.org/pdf/2405.01563)). Mapped to the design, tier selection should combine the work-at-risk rule the design already has with two classifier thresholds: auto above a high bar, auto-with-undo in a middle band, suggest below it, set per (from, to) lane pair from a labelled set of guest turns, with a higher bar for leaving a lane that holds a pending booking. The design's closed `assistant.mode.change.v1` diagnostic should record the classifier band alongside tier and undo, so the false-switch rate (auto switches the guest undid) and the clarify rate can tune the thresholds. Anthropic's advice to "find the simplest solution possible" applies: start with tier C everywhere except tier A on empty conversations, and widen auto-switching only where the undo rate stays low ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)).

## Lanes need row storage on the server and live hidden subtrees on the client

### Guest text is the only safe thing to carry across lanes

The design's isolation rule is stricter than every framework default, and the research says that is correct. The OpenAI Agents SDK hands the receiving agent the whole prior conversation "as though the new agent takes over" by default, and its `remove_all_tools` filter does not redact tool arguments or results already copied into ordinary messages ([OpenAI Agents SDK](https://openai.github.io/openai-agents-python/handoffs/)); Microsoft's handoff orchestration also passes full context and warns of cost after 3–4 hops ([MS Learn](https://learn.microsoft.com/en-us/training/modules/aaai-apply-task-decomposition-multi-agent-azure/5-ensure-handoff-reliability-context-preservation)). OWASP's LLM01:2025 mitigations call for segregating and labelling untrusted content and enforcing privilege in code ([OWASP](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)). Since agent replies, tool output and summaries are the channels injection flows through, the crossing should be an **allow-list** that copies only guest-authored text, never a deny-list filter over the old lane. A model-written summary is model output, so it must never cross either. Guest text can still carry direct injection, which is why each lane's own date authority and fail-closed id guards (ADR 0106) still apply to the carried turn.

One open design question emerges. The UX research notes that carrying booking facts (dates, party size) from Stays to Restaurants would be a differentiator if it is visible ([Microsoft Learn](https://learn.microsoft.com/en-us/agents/design-guidelines/agent-entry-points)), and CaMeL-style provenance suggests passing such facts as typed, code-validated fields rather than free text ([Simon Willison on CaMeL](https://simonwillison.net/2025/Apr/11/camel/)). Under ADR 0092/0106, chip dates and party size are already structured guest input, so a typed, guest-visible fact carry-over would not violate the guest-text-only principle. It is an owner decision, not a research conclusion, and it should be explicit in the lane ADR either way.

A2A offers ready vocabulary for the model: `contextId` groups related tasks into one session, `taskId` is always server-generated, and an agent that cannot honour a client-supplied `contextId` must reject the request rather than mint a new one ([A2A specification](https://a2a-protocol.org/latest/specification/)). That maps one thread to `contextId`, one lane to a task, and matches ADR 0106's rule that restored ids are re-keyed, never re-minted.

### Row-per-event storage fits Durable Object limits and billing

The design proposes `guest_thread_tasks (…, state_json, timeline_json, history_json, …)`, one row per lane. That improves on today's single `thread_json`, but it keeps each lane's whole timeline and model history in blobs that are rewritten on every turn and grow without bound. Cloudflare's own documentation sets a ceiling: the Durable Object limits page allows 8 MB per row, but the Agents chat docs state that "Workers SQLite rows have a hard maximum size of 2 MB" and `AIChatAgent` compacts messages at about 1.8 MB ([DO limits](https://developers.cloudflare.com/durable-objects/platform/limits/); [Agents: chat agents](https://developers.cloudflare.com/agents/api-reference/chat-agents/)). The sources conflict, so **2 MB is the safe design ceiling**. Billing points the same way: rows read are nearly free at $0.001 per million beyond 25 billion a month, while rows written cost $1.00 per million beyond 50 million, and each index-row update counts as an extra write ([DO pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/); [SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)). Whether SQLite storage billing actually began after its 7 January 2026 target was not confirmed.

The recommendation is to keep small, bounded JSON for the thread header and each task's typed state, and to store the timeline and model history as append-only rows keyed by thread, task and sequence. A turn then writes a few small rows inside one `transactionSync` call, which commits atomically and rolls back if it throws, under the existing thread lock. A cold restore loads one lane with a single indexed `SELECT`, which costs almost nothing on reads. Consume cursors synchronously, because a cursor held across an `await` has no snapshot isolation ([SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)). Keep secondary indexes few, since each one multiplies write cost. Cloudflare's split between `maxPersistedMessages`, which "controls storage only", and `pruneMessages()` for what the model sees ([Agents: chat agents](https://developers.cloudflare.com/agents/api-reference/chat-agents/)) maps onto the lane's two halves: a capped guest timeline and a separately windowed model history. Clear old tool results first, which Anthropic calls "one of the safest lightest touch forms of compaction", and keep authoritative booking facts in typed state rather than summaries ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Point-in-time recovery covers 30 days of the whole database; longer retention needs the existing export path.

### Hide lanes in place instead of detaching or moving them

On the client, the design keeps "each visited lane's transcript DOM detached in memory" and re-inserts it on switch. Re-insertion resets focus, iframe loads and running CSS animations, and `moveBefore()`, which preserves that state, is unavailable in Safari with WebKit bug 281223 still open ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/move-before); [Bram.us](https://bram.us/2025/01/16/move-elements-around-the-dom-while-preserving-their-state-with-movebefore)). The simpler approach is one live `<section data-lane>` per visited mode, each with its own scroll container, with inactive lanes hidden by `content-visibility: hidden`, now Baseline ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/content-visibility)). That property skips layout and paint while keeping rendering state, including inner scroll offsets ([web.dev](https://web.dev/articles/content-visibility)). A switch is then an attribute flip. Store `{scrollTop, atBottom}` per lane anyway, because `display: none` does not reliably preserve offsets. Avoid `hidden="until-found"`: iOS lacks it, and find-in-page revealing another mode's lane would break the isolation the guest sees ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/hidden-until-found)).

Memory caps the approach on 2–3 GB phones. No benchmark of per-node cost on Android Go was found, so the limits are engineering judgement: render the last 50–100 messages per lane as DOM, keep older ones as data, and keep only the active lane plus the two most recent warm. For streaming replies, rely on `overflow-anchor` with a bottom sentinel but keep a JS "stick to bottom when near it" fallback, since scroll anchoring reached Safari only in version 27 in September 2026 ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/overflow-anchor)).

Caching should stay in memory. IndexedDB is the right store if lanes must survive tab discards, but browsers evict best-effort storage under pressure and Safari has historically cleared script-writable storage after seven days without interaction ([MDN](https://developer.mozilla.org/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria); [WebKit](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)), and family-shared phones make persisted booking content a privacy risk. The server is always right, so a memory `Map` plus re-sync on lane activation matches the design and needs no change. Fetch inactive lanes only when first opened, never prefetch, given data prices.

Navigation should *replace* rather than push on a mode switch so Android Back leaves the chat instead of stepping through modes, using the Navigation API with a `history.replaceState` fallback ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/navigation)). A mode in the URL, such as the design's `/?start=<modeId>` deep link and manifest shortcuts, is a request the server evaluates, not authority, which preserves ADR 0004. For bfcache, Chrome stopped firing `unload` by Chrome 155 ([Chrome for Developers](https://developer.chrome.com/blog/unload-deprecated-in-chrome)), so abort in-flight turn fetches on `pagehide` and re-sync the active lane on `pageshow` with `persisted`. If the shell is served `Cache-Control: no-store`, Chrome caps bfcache at three minutes and other browsers may refuse it ([Chrome for Developers](https://developer.chrome.com/docs/web-platform/bfcache-ccns)).

## Five design changes and the conflicts behind them

The table maps each recommendation to the existing design element and states whether the research confirms or changes it.

| Design element | Research verdict | Recommended change |
|---|---|---|
| `ModePresentation` manifest | Confirmed (name, description, starters, visible active agent) | Rename `persona.name` usage to mode labels under one concierge voice; no character personas |

Several source conflicts remain unresolved and should not be treated as settled. The Durable Object row limit is 8 MB on the limits page and 2 MB in the Agents docs. Safari's support for invoker commands is 26.2 on caniuse but still blocked on one web-features snapshot. The dotLottie WASM size is quoted at both about 150 KB and about 500 KB. View transition types landed in Firefox 147, contradicting a page that says 144, and Safari's version is unknown. Whether iOS Safari 26 honours `theme-color` for installed web apps is disputed. The custom-GPT creation cut-off is reported as both 25 September and 26 October 2026. Some secondary pages still claim Firefox lacks `moveBefore`, which the feature data contradicts. Beyond conflicts, there are outright gaps: no benchmark of animation runtimes, view-transition snapshots or DOM memory on low-end Android; no published routing thresholds or hysteresis guidance; no Opera Mini share; and no 2026 confirmation of Safari's seven-day storage cap. Each of those should be measured on a real low-end device or labelled set before it hardens into policy.

## Conclusion

The research shifts the risk in this feature away from rendering technology and toward two judgement calls. The platform pieces are mature enough that a Chrome-dominant audience gets the polished path almost for free, provided every enhancement degrades to a server-rendered radio form and a hidden lane. What no source can settle is how eager automatic switching should be and how much identity each mode should carry. On the first, the GPT-5 router episode shows that the cost of a wrong silent switch is trust, not accuracy, so the safe launch is suggest-first with auto-switching earned per lane pair from measured undo rates. On the second, the retirement of GPTs and Gems suggests that modes as capabilities of one concierge will age better than a cast of named agents.

The storage change matters more than it looks. Moving from per-lane JSON blobs to row-per-event storage is cheap now, while there is one mode and one migration path through ADR 0101, and expensive later, once several lanes have grown toward the 2 MB ceiling. It also gives the closed diagnostics and the private export a natural unit, the event, which makes auditing a misrouted exchange as simple as reading the rows the guest saw.
