# Commerce surfaces after checkout child-reference fix

- Candidate HEAD: `9b98837d3bd9aec807e2ffc9a43bf35f3e5c9fce`; changes remain uncommitted.
- Root cause 1: Weaver's Basic Web runtime requires the A2UI root component ID `root`; commerce discovery/cart/order used `commerce-root`, and checkout used `checkout-root`. The protocol accepted those updates, but the resolved tree was not ready and mount output was empty.
- Root cause 2: the checkout root always listed `checkout-confirm-label`, while post-confirm statuses emitted only `checkout-confirm` containing the payment-unavailable text. Weaver accepted the protocol update but could not resolve the tree.
- Fixes: use canonical `root` for all commerce surfaces; derive the root's checkout confirmation children from the exact components emitted for that checkout status. The proposed button/label and explicit payment-unavailable copy remain unchanged.
- Relevant ADR constraints: ADR 0103 locks the exact discovery/cart/order catalogue IDs and says unavailable checkout creates no order or payment; ADR 0074 requires complete safe meaning for unsupported/failed surfaces; ADR 0081 keeps Weaver behind platform boundaries and consequential actions on platform commands; ADR 0072 requires authorization, tenant scope, freshness, idempotency and audit in the backend command path. The fix changes presentation-tree references only and preserves the existing explicit command path.
- Graph regression: `test/commerce-surface-references.test.ts` checks unique component IDs, exactly one canonical root, and every `children`/`child` reference for discovery, empty discovery, cart, order, and proposed/dispatching/payment-unavailable/payment-started checkout states; a separate assertion verifies dangling references fail.
- Command/browser regression: `test/commerce-agent-tools.test.ts` and `test/commerce-surfaces-chromium.test.ts` verify the proposed checkout and its visible confirmation control, run the actual confirmation event through the platform command, and assert the visible payment-unavailable result, no second confirmation control, and no accidental order/payment. Chromium also asserts visible facts for discovery, cart, and order and rejects fallback/empty Weaver trees.
